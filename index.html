FixLoop Studio — Master Feature Roadmap

Checklist of what’s built, what’s next, and what to add later (beginner → advanced friendly).

0 done 0 planned 0 sections Focus safety-first automation Style minimal / pro

North Star Purpose

  • [✓] Transparent repairs: every change is visible, reviewable, reversible
  • [✓] Beginner-friendly defaults (safe, minimal, explainable)
  • [ ] “Always validate” rule (tests / lint / syntax) before marking a fix as successful
  • [ ] Risk-aware strategies (low-risk first, escalate only when needed)
Design principle: FixLoop should feel like “Git + guardrails + brains”, not “mystery button that edits your code”.

Architecture Overview Blueprint

  • [ ] Core modules: Runner, Patch Manager, Validators, Strategies, UI
  • [ ] Event stream: step-by-step actions (run, detect, patch, validate)
  • [ ] Pluggable validators (lint/test/security) with a unified result format
  • [ ] Minimal persistent logs (per session) for reproducibility
Suggested folder layout

core/ (runner, patch, diff, session) • validators/ (pytest, ruff, mypy) • strategies/ (rules, ai) • ui/ (gui) • cli/ (commands)

Phase 1 — Essential Build next

  • [ ] Safe patch system: snapshot + diff preview + approve/reject + rollback
  • [ ] Project mode: run a whole folder (entrypoints + pytest)
  • [ ] Multi-file repair cycles
  • [ ] Smart fixers before AI: ruff, black, import fixes, mypy, syntax pass
  • [ ] Dependency detection (missing packages, pip checks)
Why this phase matters

This is the foundation that makes FixLoop safe + useful for real projects (and not scary to novices).

Phase 1.5 — Essential+ Stability

  • [ ] Profiles: safe / balanced / aggressive (limits + validators)
  • [ ] Reproducible environment: detect/offer venv + capture pip freeze snapshot
  • [ ] Run matrix: try multiple entrypoints / Python versions (when available)
  • [ ] Artifact outputs: save logs + diffs + reports (HTML/Markdown export)
  • [ ] “No surprises” limits: max files touched, max lines changed, max iterations

Phase 2 — Advanced Capabilities Power

  • [ ] Real AI repair engine (traceback → context → minimal patch → validate)
  • [ ] Plugin architecture (custom fixers, language modules, external tool injection)

Phase 2.5 — Advanced+ Precision

  • [ ] Context slicer: include only relevant files/functions around failures
  • [ ] Minimal repro builder (auto-generate a tiny script that triggers the bug)
  • [ ] Patch ranking: score candidates by test impact + diff size + confidence
  • [ ] Explainability: “why this change” notes attached to each patch
  • [ ] Git-aware mode: branch + commit per iteration for clean rollback/audit

Phase 3 — Professional Tooling Polish

  • [ ] Built-in terminal panel
  • [ ] Project file explorer (tree + click to open)
  • [ ] Syntax highlighting (Python first)
  • [ ] Tabbed file editing
  • [ ] Embedded test runner

Phase 3.5 — Pro Tooling+ Developer UX

  • [ ] Diff viewer: side-by-side + inline mode, with per-hunk approval
  • [ ] Project search: file search + symbol search + quick jump
  • [ ] Command palette (quick actions: run, validate, rollback, export)
  • [ ] Quick-open (Ctrl+P style) + recent projects list
  • [ ] “Session timeline” panel (what happened, in order, with links)

Phase 4 — Intelligence Layer Smart

  • [ ] Error intelligence panel (type, explanation, risk level, strategy)
  • [ ] Learning system (track frequent errors/fixes, adapt strategy)

Phase 4.5 — Intelligence+ Guidance

  • [ ] Fix recipes: curated “known good” playbooks for common failures
  • [ ] Next-step suggestions: show 2–3 options with tradeoffs (safe → bold)
  • [ ] Failure clustering: group repeated errors across runs into a single story
  • [ ] Confidence meter for each proposed fix (plus what increases confidence)
  • [ ] “Stop conditions”: detect flailing loops and recommend human review

Phase 5 — User Experience Tiers Beginner → Pro

  • [ ] Beginner mode: one-click “Fix Project” + simple explanations
  • [ ] Intermediate: show iterations + diffs + rollback
  • [ ] Advanced: strategy selection + plugin manager + language switching
  • [ ] Theme presets per skill level (novice / builder / pro)

Phase 5.5 — UX+ Adoption

  • [ ] Onboarding: guided walkthrough with a sample broken project
  • [ ] Contextual tooltips + “What changed?” explainer after each patch
  • [ ] Accessibility: font scaling, reduced motion, high-contrast theme option
  • [ ] Keyboard shortcuts cheat sheet + discoverable command hints
  • [ ] Shareable report bundle (logs + diffs + environment snapshot)

Integrations to Inject Tooling

  • [ ] Formatting: Black, Ruff, autopep8
  • [ ] Static analysis: mypy, pylint, bandit
  • [ ] Testing: pytest, coverage
  • [ ] Dependencies: pip check, pipdeptree, Poetry support
  • [ ] Future languages: Node (ESLint/Prettier), C++ (clang-tidy), Rust (cargo check), Java (Maven/Gradle)
More integrations (optional but useful)

Security: pip-audit, semgrep • Docs: pydocstyle • Packaging: build, twine checks • Performance: py-spy (later)

Quality Gates Definition of Done

  • [ ] Pre-commit: run ruff + black + basic checks before patch apply
  • [ ] CI pipeline (GitHub Actions): test + lint + typecheck on push
  • [ ] Minimum validation rule per mode (Beginner/Intermediate/Advanced)
  • [ ] Coverage goals (optional): enforce only when a project already has tests
  • [ ] Security gates for dependency issues (warn → block on high severity)
