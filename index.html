Phase 1 — Essential
Build next
▾
  • Safe patch system: snapshot + diff preview + approve/reject + rollback
  • Project mode: run a whole folder (entrypoints + pytest)
  • Multi-file repair cycles (track changes across files per iteration)
  • Smart fixers before AI: ruff, black, import fixes, mypy, syntax pass
  • Dependency detection (missing packages, pip checks)
Why this phase matters
This is the “trust layer”: before AI touches code, you always have a safe snapshot, a reviewable diff, and a one-click rollback path. It also unlocks project-wide repairs instead of single-file band-aids.
Phase 2 — Advanced Capabilities
Power
▾
  • Real AI repair engine (traceback → context → minimal patch → validate)
  • Plugin architecture (custom fixers, language modules, external tool injection)
  • Patch scoring (prefer smallest diff that passes validators)
Phase 3 — Professional Tooling
Polish
▾
  • Built-in terminal panel
  • Project file explorer (tree + click to open)

Phase 4 — Intelligence Layer
Smart
▾
  • Error intelligence panel (type, explanation, risk level, strategy)
  • Learning system (track frequent errors/fixes, adapt strategy)
  • “Stop conditions” (detect looping failures and recommend manual review)
Phase 5 — User Experience Tiers
Beginner → Pro
▾
  • Beginner mode: one-click “Fix Project” + simple explanations
  • Intermediate: show iterations + diffs + rollback
  • Advanced: strategy selection + plugin manager + language switching
  • Theme presets per skill level (novice / builder / pro)
Phase 6 — Safety & Governance
Guardrails
▾
  • Change budgets (max files touched, max lines changed, max iterations)
  • Per-hunk approvals (accept/reject individual diff chunks)
  • Dry-run mode (generate patches + reports without writing files)
  • Safety policy presets: safe / balanced / aggressive
Phase 7 — Reproducible Environments
Reliable
▾
  • Auto-detect + offer venv creation and activation instructions
  • Capture environment snapshot (python -V, pip freeze, OS info)
  • Deterministic runs (store commands + args + workdir per session)
  • Cache artifacts (logs, diffs, reports) per run
Phase 8 — Validation Pipeline
Proof
▾
  • Unified validator runner (lint → typecheck → tests → security)
  • Definition of Done gate (must pass selected validators to mark success)
  • Configurable thresholds (e.g., coverage only if tests exist)
  • Validator summaries in the final report (what ran, what failed, why)
Phase 9 — Diff & Review UX
Transparency
▾
  • Side-by-side diff viewer (inline + split view)
  • Annotate diffs with “why this changed” notes
  • Review queue (stage multiple patches, approve in order)
  • Quick rollback from the UI (one-click revert to snapshot)
Phase 10 — Git Integration
Audit
▾
  • “Session branch” mode (create branch automatically for fixes)
  • Commit-per-iteration (clean history + easy rollback)
  • Export patches (.patch) + release notes summary
  • Auto-detect uncommitted changes and warn before modifying
Phase 11 — Performance & Scalability
Fast
▾
  • Job queue for repairs (multiple targets, scheduled runs)
  • Parallel validators where safe (e.g., lint + typecheck)
  • Incremental analysis (only re-check touched files when possible)
  • Resource limits (CPU/mem caps, smart timeouts, cancellation)
Phase 12 — Observability & Reporting
Track
▾
  • Session timeline (every action recorded as events)
  • Report export: JSON + HTML + Markdown bundle
  • Metrics: iterations, patch sizes, pass rate, top error types
  • Failure clustering across runs (group repeating issues)
  • Opt-in telemetry dashboard (aggregate performance + common failures)
Phase 13 — Security Hardening
Secure
▾
  • Add security scanners (bandit, pip-audit, optional semgrep)
  • Sandbox execution options (restricted subprocess policies)
  • Secret detection (warn if keys/tokens appear in diffs)
  • Path-safety checks (avoid writing outside project root)
Phase 14 — Multi-Language Expansion
Beyond Python
▾
  • Language adapter interface (common runner + validators + patching)
  • Node/TS: ESLint + Prettier + test runner integration
  • Rust: cargo check + clippy integration
  • C++ / Java: clang-tidy + Maven/Gradle build/test hooks
Phase 15 — Enterprise Readiness
Teams

  • CI integration modes (GitHub Actions / GitLab pipelines)
